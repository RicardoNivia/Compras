# Mi día, alertas y notificaciones

Detalle movido desde `CLAUDE.md` (sin cambios de contenido). Las convenciones generales siguen en `CLAUDE.md`.

- **Mi día y alertas (`lib/pendientes.js`, `lib/alerts.js`, `app/api/pendientes`, `app/api/agent/review-pendientes`, `frontend/components/MiDiaView.jsx`)**: no Prisma model — one engine, `getPendientes(user)`, computes what each ROLE has to do today (sections with severity `critico`/`atencion`/`info`, each item `{ ref, titulo, contexto, dias, detalle, nivel, href, mio }`): radicar → legalizadas por radicar + radicadas sin valoración de Nova; legalizar → por legalizar + rechazadas; registro → solicitudes atrasadas (>8 días hábiles urgente, desde 5 atención) + rechazadas; proveedores → desactualizados, estancados (>15 días), checklist incompleto, NIT provisional + días al corte; Tesorería (cualquier rol con verTesoreria) → pagos programados vencidos en P (`tesVencidos`) y lo que no cuadró al importar la plantilla (`tesAlertas`, ver docs/claude/tesoreria.md); admin → todo + presupuesto ≥80%, compras mal valoradas por Nova y entregas fuera de plazo. Reuses `lib/alerts.js` (solicitudes pendientes, SLA, presupuesto) and the Proveedores module; `SECCIONES` in `pendientes.js` is the catalog (add a section there and give it `roles`). Outputs read the same engine so they never disagree: the page `/alertas` ("Mi día y alertas", recomputed on every visit — no refresh button, no sidebar counter — and the landing page after login only for roles without the Dashboard; everyone else still lands on `/dashboard`) and Nova's `mis_pendientes` tool; `review-pendientes` is Nova's role-aware day summary. Gated by `viewAlertas` (default: every role, Proveedores included). There is intentionally no email channel: SMTP-AUTH is blocked (see `lib/mailer.js` `MAIL_MAINTENANCE`). The `/alertas` page is now "Alertas y notificaciones", with tabs Mi día / Bandeja / Mis notificaciones (see below).
- **Notificaciones configurables por prompt (`lib/notificaciones*.js`, `lib/teams.js`, `app/api/notificaciones/*`, `frontend/components/notificaciones/*`, design in `docs/notificaciones-diseno.md`)**: each person writes what they want to be told; Nova (`notificacionesNova.js#interpretarPedido`) turns it into a rule or asks about what is ambiguous, and the server always adds the mandatory questions (`preguntasFaltantes` in `notificacionesCatalogo.js`: hora, festivo, si no hay resultados, fecha de solicitud vs creación, alcance). Execution never uses AI: `notificacionesConsultas.js` holds fixed queries reusing Mi día (`pendientes.js#itemsDeSeccion`) and `alerts.js`; `notificacionesMotor.js` runs one rule (origins `programado`/`recuperado`/`manual` — the "Enviar ahora" button, all recipients — /`prueba` — only to the tester), with a unique `clave` per execution (`n{id}|{día}`) so the scheduled one never sends twice a day. `notificacionesScheduler.js` (started in `instrumentation.js`) checks every minute, retries Teams on 429/5xx and purges history >180 days. Security: one data source per rule; creator AND every recipient must be able to see it (`notificacionesPermisos.js#puedeVerFuente`), re-checked on every run (owner loses access → `pausada_por_permisos`). Admins manage everyone's rules. Limits: 10 notifications created per person (any state, checked on create; "Mías" is not paginated) and 6 recipients. Recipients can unsubscribe (audited `baja`/`alta`). Channels: app (always, the Bandeja + red counter of unread in the top-bar bell — only this module, never Mi día) and Teams (one Power Automate webhook flow that DMs each recipient; `TEAMS_MODO` desactivado/simulado/real, `TEAMS_WEBHOOK_URL`, `TEAMS_CLAVE_FLUJO`, `TEAMS_DESTINO_PRUEBA` redirects everything locally, `APP_URL`; `npm run teams:probar`). The "¿Por dónde le llega?" channel picker shows in every environment (`NOTIFICACIONES_ELEGIR_CANAL=0` hides it); Teams only works where the server has `TEAMS_*` set. Email is shown disabled. Gated by `viewNotificaciones` (every role by default). **Event-triggered rules (phase 2, `notificacionesEventos.js`)**: `disparador: "evento"` + `evento` (catalog `EVENTOS`: compra.creada/legalizada/rechazada/radicada/valorada/calificada/entregada/anulada/eliminada/actualizada (any field, with before→after), proveedor.creado/actualizado/eliminado/ciclo_cambio, presupuesto.actualizado, presupuesto.umbral — 80 % / 100 % at three levels: general, área and categoría when the year is per category; areas matched by exact name like `alerts.js`; crossing 100 % at once only sends "se excedió". Filters: área, proveedor (NIT or name) on purchase/provider events, nivel and soloExcedido on thresholds) + `agrupacion` (inmediato / cada_15_min / resumen_diario — only the daily summary has an hour; events never ask hour or holiday). Writers publish to the `EventoNotificacion` outbox fire-and-forget (`publicarCambiosDeCompra` and `deleteRecord` in `records.js`, `calificaciones.js`, `proveedores.js` (create/update/delete) and `proveedoresCiclo.js#cambiarClasificacion`, `proveedoresCiclo.js#cambiarEstadoCiclo`; Nova valuations are detected by sweep, `detectarValoraciones`, since app/auto/script all save them; budget thresholds by `revisarUmbralPresupuesto` — called on every purchase save and every budget change —, once per level/year/threshold via the unique `clave`; `presupuestos.js` publishes `presupuesto.actualizado` on create/modify/delete/mode change). **Add new events there, never block the original write.** Received notifications show which rule they come from, and `components/notificaciones/AvisosEnVivo.jsx` (in the `(app)` layout) polls every 20 s and pops an on-screen toast for every recipient. `notificacionesCatalogo.js` is duplicated in `frontend/lib/` — keep both in sync.

# Estudio de informes, Claude MCP y agente al desplegar

Detalle movido desde `CLAUDE.md` (sin cambios de contenido). Las convenciones generales siguen en `CLAUDE.md`.

- **Estudio de informes (`lib/reports.js`, `lib/reportContent.js`, `lib/reportPdf.js`, `lib/reportSchedule.js`, `lib/reportEdiciones.js`, `lib/reportNova.js`, `lib/reportScheduler.js`, `lib/reportJobs.js`, `app/api/reports/*`, `frontend/components/informes/*`)**: the user asks Nova for a report in natural language (`/api/reports/nova/armar`) or starts from a template (`PLANTILLAS` in `reportNova.js`); the result is a `ReportConfig` (`tipo: "estudio"`) made of `bloques` (ia/texto/kpi/grafico/tabla/presupuesto/pendientes/fueraPlazo/proveedoresValoracion/cicloProveedores). Rule: Nova decides structure and text, never figures — kpi/chart/table blocks are computed from real data, ia blocks answer over exact aggregates of the report period — all of a report's ia blocks (plus the email `{resumen_nova}`) go in ONE AI call (`resolverIaEnLote`), and each text is keyed by a hash of the period data + its question, reused while the data is unchanged (in-memory 24 h + `content._ia` of the last edition); `editarConNova` sends a trimmed catalog (text-only edits skip the charts catalog, the Dashboard guide only when mentioned). The editor (`EditorDiseno.jsx`) edits blocks by hand or via `/api/reports/nova/editar`, draws the content as an A4 page, and every KPI/chart value opens `/api/reports/cifra` (deterministic "where does this number come from"). Preview = the real PDF (`render-pdf`, `estudio: true`). Scheduling (`reportSchedule.js`): diaria/semanal/mensual/mensual_semana ("primer lunes hábil")/ultimo_habil/unica, skipping Colombian holidays; natural-language rule via `/api/reports/nova/programacion`; optional `condicion`. The in-process scheduler (every minute, from the configured time on, once per day, only `tipo: "estudio"`, active, non-draft) creates a `ReportEdicion` (archived PDF + resolved subject/message with `{mes}`/`{periodo}`/`{resumen_nova}`… + figures summary). Delivery: only **"Lo envío yo"** works today — the edition stays `por_enviar`, shows up for its `responsables` in Mi día (`informesPorEnviar` section) and the user downloads the PDF, opens Outlook via mailto and marks it sent (`EnviarInformeModal.jsx`). `entrega: "correo"` sends automatically only when `MAIL_MAINTENANCE` is off; Teams is shown as "Próximamente" and rejected server-side. Editions, downloads and sends are audited (`entityType: "informeEdicion"`, `recordId` = report id → `/api/reports/{id}/actividad`). Long AI operations run as background jobs (`reportJobs.js`, polled at `/api/reports/jobs/{jobId}`). **Alcance** (scope): a report can be limited to some categories and/or areas (`contexto.filtros = { areas, categorias }`, card "Alcance" in Datos del informe, `components/informes/AlcanceInforme.jsx`); Nova sets it from the request ("lo consumido en imprevistos administrativos" → `filtroCategorias`, names resolved against the real ones ignoring accents/case or by all words) and can change it when editing. It is applied with `conAlcance()` (AsyncLocalStorage in `reportContent.js`) inside `loadRecordsAndPresupuestos`, so KPIs, charts, tables, Nova sections (their cache key includes the scope), the edition summary and `/api/reports/cifra` all see only those purchases; the PDF subtitle and the page header say "Solo Categoría: …". With an area filter the budget is limited to those areas; with a category filter the area budget is compared with that category’s spend. Everything gated by `viewReportes` (default: admin only). Reports from the old block builder keep working but are not scheduled until opened and activated in the Studio.
- **Claude MCP — SOLO PARA ADMIN, en local y en producción (`lib/mcpGate.js#mcpPermitidoA(role)` = rol `admin`, validado directamente; NO es un permiso de la Matriz y no se puede asignar a ningún otro rol: no existe en `FEATURES` y `POST /api/permissions` lo rechaza con 400). Un no-admin no ve el ítem del menú, `/conectar-claude` lo redirige a Registros (`frontend/middleware.js`), recibe 403 en `/api/tokens*` y sus tokens no autentican en `/api/mcp`) (`lib/mcpServer.js`, `lib/mcpTokens.js`, `app/api/mcp`, `app/api/tokens/*`, `frontend/components/ConectarClaudeView.jsx`)**: servidor MCP de SOLO LECTURA (JSON-RPC sobre HTTP, sin estado, sin SSE) para que cada persona consulte el panel desde su propio Claude (Claude Code / Claude Desktop vía `mcp-remote`; claude.ai web no, haría falta OAuth) — el consumo de IA va a la cuenta de cada quien, no a `ANTHROPIC_API_KEY`. Auth: token personal `cmp_…` (modelo `TokenAcceso`, solo se guarda el hash SHA-256; se muestra una única vez; vigencia 30/90/180/365 días; máx. 5 activos por persona; revocable por su dueño o un admin) en `Authorization: Bearer`; `/api/mcp` es público en `middleware.js` porque no usa cookie. Solo los tokens de usuarios `admin` autentican (si el dueño deja de ser admin o se desactiva, sus tokens dejan de servir al instante) y cada herramienta pasa por los mismos permisos que usa Nova (`viewAgenteIA`, `viewPresupuesto`, `viewAuditoria`, `viewProveedores`). Herramientas: las MISMAS de Nova, reutilizando `lib/agentTools.js` (`buildToolDefs`/`buildToolExecutor`, una sola fuente — agregar una herramienta a Nova la publica también en el MCP), filtradas por `viewAgenteIA` + `viewPresupuesto`/`viewAuditoria`/`viewProveedores` igual que el chat, con resultados recortados a 15k chars; no hay ninguna que escriba (no agregar sin revisar riesgo de inyección de prompts por texto libre). Auditoría: crear/revocar token (`entityType: "tokenAcceso"`) y cada consulta (`entityType: "mcp"`, acción `consultar`). Límite 60 mensajes/min por persona. Ver `docs/mcp-despliegue.md`.
- **Agente al desplegar (`lib/agenteDespliegue.js`, from `instrumentation.js`)**: once per deploy (fixed id `MARCA` in `audit_logs`, so only one instance runs it; change `MARCA` to repeat it in a future deploy), 2 min after startup it finishes the comment thumbs and runs the evaluation agent over ALL executed/closed activities (`iniciarTrabajo(..., { todas: true })`, only reachable from there) and their dashboards. If it fails to start, the mark is removed and it retries on the next restart. `AGENTE_AL_DESPLEGAR=0` disables it.

# Frontend (`frontend/`)

Detalle movido desde `CLAUDE.md` (sin cambios de contenido).

- **Routing**: real Next.js routes per section (not client-side tabs) — `app/page.js` redirects to `/dashboard` or `/registros` depending on role; `app/dashboard/page.js`, `app/registros/page.js`, `app/usuarios/page.js`, `app/auditoria/page.js`, `app/maestros/page.js`, `app/presupuesto/page.js`, `app/alertas/page.js`, `app/informes/page.js` are async Server Components that call `getSessionUser()` (from `lib/auth.js`, HTTP to the backend) + the relevant guard, fetch data via `lib/backendFetch.js` (HTTP to the backend, not a direct DB call), and render `components/AppShell.jsx` (sidebar + topbar shell) wrapping the page's client view. All are `export const dynamic = "force-dynamic"`. The guard pattern is `user.permissions?.<feature> ?? canX(role)` — it prefers the runtime Matriz de permisos value returned by `GET /api/auth/me` and only falls back to the static `lib/roles.js` helper if `permissions` wasn't returned.
- **Modules and navigation (`lib/modulos.js`, `components/ModuloShell.jsx`, `components/Sidebar.jsx`)**: the app is split into modules — **Compras** and **Bienestar**. `ModuloShell` (in the `(app)` layout) sets `data-modulo` on `.app-shell` from the route (`moduloDeRuta`; general routes like Alertas/Nova/Usuarios/Auditoría keep the last module via the `modulo` cookie, read server-side so nothing flickers). **Design line 2026** (root tokens + "Tema por módulo" + the final "Línea de diseño 2026" block of `globals.css`): one system (neutrals, type, page structure, state colors) and one line per module that only changes color (`--accent`/`--secondary`, plus `--marca`/`--marca-2` = the module's vivid color, the same in light and dark, for primary buttons, the rail and banners with white text), shape (`--r` cards, `--r-b` buttons, `--r-s` fields) and the header motif: Compras cobalt, contained corners, dot grid; Bienestar green, round shapes, pill buttons; Tesorería violet, square corners, monospaced figures; Fundación keeps its sky blue inside Bienestar. New UI must use those tokens, never hard-coded radii or brand colors. Cronograma, Trayectoria and Historias keep their own layout and only inherit colors and animations. The Sidebar has two pieces, both fixed at full height (they never scroll with the content): a dark rail with the modules the user has at least one item of (each in its color; Alt+1/2/3 switch directly), the search (Ctrl+K), the light/dark theme button (cookie `tema` → `data-theme` on `<html>`, set server-side in `app/layout.js`; without it the OS preference applies) and the button that pins the panel (cookie `menu` = `abierto`; by default the panel takes no space and uses the mechanic of the Selvana menu: it keeps its full-width design and is revealed over the content when the mouse comes near the menu — clip-path reveal in 200 ms after a 70 ms wait, options entering staggered —, or with a click on a module for touch screens, and it hides when the mouse leaves or with Esc); and the panel with the active module menu in groups (Compras: Operación / Planeación; Bienestar: Bienestar / Fundación; Tesorería) , user, change password and logout. **Lo general is not a module**: Alertas, Nova, Usuarios y roles, Auditoría and Conectar con Claude are direct links in the rail below the modules (`GENERALES` in Sidebar.jsx, class `nav2-directo`, short label `corto`): each goes straight to its page without opening a panel (hovering them does not reveal the module panel), and those routes keep the last module's theme; they are no longer repeated at the end of every module menu ("Mi correo" is hidden from the menu and the search since November 2026, its page and agent still exist). The top bar has, next to the bell, a button that opens the current page in another browser tab (`components/DuplicarPestana.jsx`). Changing module plays a color wave (`.modulo-ola`, `ModuloShell`). The rail's brand is an animated S (`MarcaYFormas.jsx#MarcaAnimada`) and small shapes fall diagonally through the menu (`FormasCayendo`: boxes in Compras, hearts in Bienestar, coins in Tesorería; the login's left panel uses the same pieces with the three shapes mixed). Items are filtered by the Matriz (`feature`, fallback `show` from `lib/roles.js`). **A new page must be added to `GRUPOS`/`GENERALES` in Sidebar.jsx and, if it belongs to a module, to `RUTAS` in `lib/modulos.js`.** Charts: every chart uses the shared kit in `components/charts/chartKit.js` (staggered entry, counting numbers, hover dim + Tooltip, `useMorph` transitions) — `BarChartSvg`, `StackedBarChartSvg`, `PieChartSvg`, `ComboChartSvg` (bars + line, two axes) and `HBarChartSvg` (rankings); never hand-roll a chart outside it. Switching tabs inside a page goes through `lib/crossfade.js` (`onClick={() => crossfade(() => setTab(k))}`, View Transitions crossfade; instant without support or with reduced motion).
  - `RegistrosPageClient.jsx` → `RegistrosView.jsx` — the records table (filters, table, pagination, CRUD via `RecordModal.jsx`/`DetailModal.jsx`); both take a `currentUser` prop and gate the add/edit/delete/radicado-toggle UI through the same `lib/roles.js` helpers used server-side. Mutations go through `lib/api.js` (`fetch("/api/records...")`, proxied to the backend by `next.config.js` rewrites).
  - `DashboardView.jsx` — the analytics view (KPIs, charts), only reachable by roles where `canViewDashboard` is true.
  - `UsuariosView.jsx` / `UserModal.jsx` — user administration, gated by `viewUsuarios`, calling `/api/users` (proxied to the backend); also renders `PermissionsMatrix.jsx` (the Matriz de permisos editor, `/api/permissions`).
  - `MaestrosView.jsx` (`app/(app)/maestros/page.js`, gated by `viewMaestros`) — catalog admin for the records form's dropdown options.
  - `PresupuestoView.jsx` (`app/(app)/presupuesto/page.js`, gated by `viewPresupuesto`) — per-year/per-area budget configuration.
  - `AlertasView.jsx` (`app/(app)/alertas/page.js`, gated by `viewAlertas`) — pending/overdue/budget-risk alerts.
  - `InformesView.jsx` (`app/(app)/informes/page.js`, gated by `viewReportes`) — automated report builder/scheduler.
  - `components/charts/*` (`BarChartSvg.jsx`, `StackedBarChartSvg.jsx`, etc.) — charts are hand-rolled SVG React components, not a charting library, to match the original's exact visual behavior.
  - `ExportMenu.jsx` — CSV/PDF/Word export dropdown, rendered inside the Registros page.
- **`lib/businessDays.js`**: Colombian business-day/holiday logic ported from the original — fixed holiday list + Meeus/Jones/Butcher Easter algorithm + `nextMonday` shifting for "Emiliani" holidays. Change with care; this must match the original's date math exactly.
- **`lib/format.js`**: currency/number/date formatting helpers (`fmtCOP`, `fmtCompact`, `fmtNum`, `esDecimal`, `fmtPesos`, `fmtDateDisplay`) ported from the original — used throughout the UI for consistent es-CO formatting.
- **`lib/exportHelpers.js`**: low-level export helpers (`saveBlob`, `todayISO`) used by `ExportMenu.jsx`, which builds CSV (semicolon-delimited, BOM, `;`/quote escaping to match Excel's es-CO CSV dialect), PDF (`jspdf` + `jspdf-autotable`), and Word (`docx` npm package — a real `.docx`) exports, plus a full-dashboard PDF snapshot via `html2canvas` + `jspdf` in `DashboardView.jsx`.
- **`app/globals.css`**: CSS custom properties / design tokens of the 2026 design line (Plus Jakarta Sans headings / Inter body / IBM Plex Mono figures; Nunito and Roboto are still loaded only for the report documents that imitate the PDF) — light mode + `prefers-color-scheme: dark` + explicit `[data-theme]` overrides, plus every component class (`.topbar`, `.sidebar-*`, `.kpi-row`, `.table-card`, `.modal-*`, `.gauge-*`, `.login-*`, `.spinner`, etc.). New UI should reuse these existing classes/tokens rather than introducing a new styling system.

- **Tooltips de texto largo** (`desc-tooltip-wrap` / `desc-tooltip-bubble`): `components/TooltipFlotante.jsx` (montado en `app/(app)/layout.js`) copia la burbuja a una capa fija en `<body>` al pasar el mouse. Así ninguna fila siguiente, tabla con scroll ni columna fija la recorta. No hace falta nada por tabla: basta el marcado de siempre.
- **Exportar a Excel** (`components/BotonExcel.jsx`): every table that lists rows has the button (usually in the `table-footer`, next to the count). `columnas = [{ t, v(fila) }]`; pass `filas` (everything already filtered, not just the page) or `obtener` (async: brings every page from the backend, as Auditoría and Tesorería do). In Bienestar, `PiePagina` takes `excel={{ nombre, hoja, columnas, filas }}`. Money goes as a number, not formatted text. **A new table must have it too.**
- Kit charts that accept negative values: `DivergentBarChartSvg` (cash in above, cash out below, net as a line; for cash flow) and `LineChartSvg` (several series with a zero line; for balances per bank).
- **Empty states** (in `globals.css`, the «Estado vacío» block): every `.empty` shows the module-colored illustration (a tray icon on a `--marca` → `--marca-2` gradient, a halo and a slight float), with the text centered. `.compacta` (and any `.empty` inside `.modal`) is the small version.
  - With a title, your own icon or an action, use `components/EstadoVacio.jsx` (`titulo`, `icono`, `accion`, `compacto`).
  - Inside a table, `td > .empty` centers on the visible part of `.table-scroll`.
  - The agents' `ag-vacio` uses the same illustration.
  - **Never leave a gray loose «No hay…» text: use one of the two.**
